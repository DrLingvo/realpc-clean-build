# timing_tests — оценка детектируемости ВМ

Гостевой набор тестов, который **измеряет, насколько ВМ отличима от железа** по таймингам и
возможностям CPU. Это диагностика, а не «защита»: он показывает, что скрыть удалось, а что нет.

## Что проверяется

| Тест | Что меряет | Природа |
|---|---|---|
| `rdtsc_cpuid_rdtsc` | латентность VM-exit (CPUID всегда перехватывается KVM) | **known limitation** — на ванильном KVM не скрывается |
| `cache_latency` | латентности L1/L2/L3/RAM (pointer-chasing) | под EPT близко к железу; характеризует хост |
| `tsc_sync` | рассинхрон TSC между vCPU | actionable |
| `hpet_tsc_ratio` | стабильность отношения TSC/время | actionable |
| `pmu_check` | наличие архитектурного PMU (CPUID 0x0A) | actionable (включить PMU в `-cpu`) |
| `rapl_check` | доступность и рост RAPL (валидирует host-sensors) | actionable |

## Запуск

```bash
# на хосте Proxmox (в госте нужен qemu-guest-agent):
TRANSPORT=qm   ./run_tests.sh <vmid>
# любой гость по ssh:
TRANSPORT=ssh  ./run_tests.sh root@guest-ip
# прямо внутри гостя:
TRANSPORT=local ./run_tests.sh
```
`analyze.py` сравнивает результаты с `reference/thresholds.json` и печатает вердикт
(`OK` / `TELL` — устранимый признак / `KNOWN` — известное ограничение / `SKIP`). Код возврата
1, если есть устранимые `TELL`.

## Как читать

- `TELL` — то, над чем можно работать (нет PMU, нет RAPL, рассинхрон TSC). Например, `pmu_check:
  TELL` чинится добавлением `pmu=on`/нужных флагов в `-cpu`; `rapl_check: TELL` — включением
  host-sensors и `modprobe msr` в госте.
- `KNOWN` — то, что на обычном KVM не спрятать (латентность VM-exit). Подробнее — в разделе
  «Известные ограничения» основного README.

## Пороги

`reference/thresholds.json` — **shape-based** (коэффициент вариации, стабильность отношения,
наличие возможностей), а не абсолютные циклы: абсолютные значения зависят от частоты и
микроархитектуры и плохо переносятся. Источники — Intel SDM / AMD PPR + замеры. Правьте под
свой хост; значения консервативные.

## Замечания по реализации

- `rdtsc` сериализован (`lfence`/`rdtscp`), иначе измерения смазываются out-of-order.
- TSC калибруется по `CLOCK_MONOTONIC`, чтобы выводить и наносекунды (циклы непереносимы).
- `rapl_check`/MSR требуют root и `modprobe msr`; без них тест аккуратно пропускается.
- HPET-счётчик напрямую из userspace недоступен (MMIO/root), поэтому когерентность таймеров
  меряется через `CLOCK_MONOTONIC_RAW` — тот же путь таймкипинга ядра.
